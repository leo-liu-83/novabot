# 架构与运行模型

本文从使用者视角说明 NovaBot 由哪些部分组成、数据放在哪里，以及会话和安全边界如何工作。

## 1. 总体结构

```text
┌─────────────────────────────────────────────┐
│  TUI (Textual)      Web 控制台 / HTTP API    │
│        │                    │               │
│        └──────┬─────────────┘               │
│               ▼                             │
│        会话与身份服务                        │
│               │                             │
│               ▼                             │
│        Agent 运行时 + 工具                   │
│   模型 / 技能 / 附件 / 搜索 / MCP / 记忆     │
│               │                             │
│               ▼                             │
│     SQLite + 本地文件系统                    │
└─────────────────────────────────────────────┘
```

核心特点：

- **本地优先**：会话、账号、技能、记忆和配置都保存在本机
- **TUI 与 Web 共用数据**：同一套会话、消息、checkpoint 和账号，换端可以继续
- **服务端签发会话键**：会话 ID 同时用于消息、checkpoint 和附件目录，不接受客户端自造
- **能力分层**：身份、执行档位、技能放行、网络访问和 MCP 授权是几条独立边界

## 2. 主要组件

| 组件 | 作用 |
|---|---|
| TUI | 终端交互界面；适合本机操作和首次初始化 |
| Web 控制台 | 浏览器界面；与 TUI 共用后端会话 |
| HTTP API | 登录、会话、聊天 SSE、模型目录、技能、MCP、管理接口 |
| Agent 运行时 | 组织模型请求、工具调用、上下文压缩和事件流 |
| 模型层 | 统一接入 OpenAI 兼容接口，支持多 provider 和动态模型列表 |
| 技能层 | 系统 / 共享 / 私有三层技能，带扫描、放行和内容哈希 |
| 文件与附件 | 工作区文件、会话附件、文档转换和图片输入 |
| 网络能力 | 搜索 provider 降级链、网页抓取和 SSRF 防护 |
| MCP | 外部工具接入，按 server / 工具分级授权 |
| 存储 | SQLite 数据库 + 会话与用户目录 |

## 3. 数据目录

默认位置 `~/.novabot/`（Windows 为 `%USERPROFILE%\.novabot\`）：

```text
~/.novabot/
├── novabot.json              # 用户配置：模型、网络、MCP、附件等
├── ui.json                   # TUI 主题与语言
├── data/
│   ├── novabot.db            # 会话、消息、账号、项目、技能审查、配额等
│   └── login.json            # TUI 登录凭证（remember_login 时）
├── sessions/
│   └── <thread_key>/         # 每个会话的附件、压缩历史、大工具结果
├── users/
│   └── <uid>/workspace/      # 登录用户的工作区、技能、提示词、记忆
├── workspace/                # 匿名/公共工作区
└── prompt.md                 # 公共自定义指令（可选）
```

发布包内的 `config/config.json` 是内置默认配置，随版本分发；用户配置只写 `~/.novabot/novabot.json`。

项目是个例外：项目行（名称、目录、推荐技能）在 `novabot.db`，但**项目知识留在项目目录内**——项目根的
`AGENTS.md` 与 `.novabot/notes/*.md`，随项目目录一起迁移或备份，不进 `~/.novabot/`。

## 4. 身份与会话

### 4.1 身份

- **匿名**：不需要登录，使用公共工作区
- **普通用户**：注册后拥有独立工作区、私有技能、人格和记忆
- **管理员**：管理账号、执行天花板、搜索配额、全局 provider 和 MCP 授权

多用户模式下必须有且只有一个管理员，首次启动时在本机 TUI 创建。

### 4.2 会话

- 会话由服务端签发唯一 ID
- TUI 和 Web 读写同一套 `sessions` / `messages`
- 消息历史支持分页；上下文由服务端根据 checkpoint 和预算恢复
- 删除会话时会等待在途请求结束，再清理消息、checkpoint 和附件
- 会话可以归属项目（`sessions.project_id`），归属后工作根、文件边界和注入的项目知识都随项目走

### 4.3 项目

- 项目是"登记一个已有目录"：名称 + 目录 + 描述 + 推荐技能，同一账号下活动项目的名称与目录唯一
- 归档只置 `archived_at`，不删除目录、不移动文件；同名或同路径可在归档后重新登记
- 项目会话的工作根是项目目录；项目知识来自项目根 `AGENTS.md`（常驻注入，12 KB 截断）与
  `.novabot/notes/*.md`（只列文件名索引，最多 200 个、8 KB）
- 归属关系只影响之后的上下文与文件边界，不会搬迁已有会话、附件或文件

## 5. 安全边界

NovaBot 的安全模型是**多层限制**，不是单一开关：

| 边界 | 作用 |
|---|---|
| 身份天花板 | 决定账号最高能到哪个执行档位 |
| 执行档位 T0–T4 | 决定能否执行命令、是否逐条确认 |
| 技能审查 | 脚本技能先扫描再放行；未放行不加载 |
| 网络策略 | 抓取确认、域名 allowlist、SSRF 防护 |
| MCP 授权 | admin 决定是否开放；用户决定 server / 工具怎么用 |
| 确认门 | 写文件、删除、部分 MCP 工具和网页抓取可要求确认 |
| 项目边界 | 项目会话限定在项目目录内；越界路径与敏感文件走确认，T4 收窄为"项目内免确认" |

这些边界不能互相替代。例如：MCP 工具不受执行档位约束；技能扫描通过也不代表没有风险。

## 6. 运行方式

### TUI

```bash
novabot
```

### Web

```bash
novabot web --host 127.0.0.1 --port 9000
```

默认监听 `0.0.0.0`，多用户部署前请收紧到本机或反向代理层加鉴权。

### REPL

```bash
novabot repl
```

REPL 是轻量终端会话，不提供 TUI 的完整可视化，但共用模型和会话能力。

## 7. 扩展点

- 模型：在 `novabot.json` 增加 provider / model，或用 `dynamic_models` 自动发现
- 技能：放进系统、共享或私有技能目录
- 网络搜索：用户自备 provider 或全局 provider
- MCP：系统层写内置配置，用户层通过 `/mcp` 添加
- 人格与记忆：编辑 `SOUL.md`、`USER.md`、`prompt.md` 和 `memory/`

具体字段和命令见对应手册。
